# Medar interface — Living / زنده

Selected by the user on 2026-10-15. Phone first; full laptop layouts. This replaces the earlier four-destination/Today notebook proposal.

## Structure

- Information is the default home: actual weekly tag goals, notices, weekly activity/streak, selected priorities, daily Mother and English cards, existing encouragement and service status.
- Tasks contains separate Today/All tasks views. Today starts with planned work, title-only capture, overdue/completed folds and native due reminders. All tasks retains its full filter/sort/recurrence manager and full editor access.
- Primary navigation: Information, Tasks, Calendar, English, More. Mother is highlighted under Information; its complete page is also reachable from More. English's complete four-tab page remains directly accessible.
- Calendar retains the original Jalali month/day views, existing-task picker, recurring previews and editor calendars.
- More uses compact icon/name tiles without explanatory subtitles. Every destination opens its complete original module.
- Settings owns tags, weekly targets/reasons and full device/account/backup controls. Existing specialized section settings remain where they were.

## Visual foundations

- Production presentation is `ui-redesign.css` / `ui-redesign.js`; `installMedarPresentation()` runs before auth initialization. Existing original renderers/editors/persistence remain authoritative. The selected direction's layouts are derived from the full-app comparison, not the reduced interaction prototype.
- Canvas #F7F3E9; surface #FFFEFA; forest #204D3D; sage #DCE7D7; text #243B31; muted #65705F; line #DEE1D3. Dark forest is concentrated in the goal panel and phone navigation.
- Vazirmatn, existing SVG icon helper, original logo. Headings 25–31px, body 13–14px, quieter metadata. Full mixed-language task titles wrap without line clamp.
- Separate task surfaces with aligned checkbox/title/edit/options columns; empty subtasks stay hidden, while the full editor always creates the first subtask.
- Phones through 700px have an inset floating bottom navigation; 701–1000px a narrow sidebar; larger widths a full sage sidebar. Respect safe areas. No unnecessary animation; reduced-motion and visible keyboard focus are preserved.
- Editor is a bottom sheet with an independently scrollable full form and sticky save/cancel actions. Larger screens use two columns. No fields are removed to save space.

## Behavior and data boundaries

All writes use existing handlers. Quick capture passes its title to the native `confirmTaskEditor()` routine; no hidden DOM editor or preview service enters production. Information uses actual state and existing goal/streak calculations. A summary never marks reports read; pending review proposals keep their notice. Existing Mother `showOnToday` data field is retained for compatibility and relabeled as display on Information; scheduling/push semantics remain unchanged.

The existing service-worker update protection from latest main is preserved. Cache v54 includes both UI assets. No backend/schema change or new UI framework.

## Review and verification

`artifacts/living-redesign/index.html` is generated by `tests/build-living-preview.py` from current production files with sample state and mock service writes. Device/account actions are isolated; no service worker or live credentials. `tests/living-redesign-check.cjs` covers key UI workflows and eight widths. Live backend, AI, device push, full offline/realtime and backup restore remain outside these mocked checks. The 90-checkpoint feature inventory remains the release checklist; do not present mock UI checks as full parity certification.

Task editor keyboard behavior: native chip buttons, meaningful labels, heading focus on open, inert background, contained Tab, Escape cancel and return focus. Content skip link preserves the current route.
